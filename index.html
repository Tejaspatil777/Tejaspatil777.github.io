DarshanAI Face Recognition Attendance

DarshanAI (Meritendance) is an AI-powered attendance application that automates classroom attendance with face detection and face recognition. It combines a Flutter mobile app, a Java Spring Boot 3 backend, a Python AI service and a PostgreSQL database.

Face enrollment flow

  1. The student opens Face Enrollment and the live camera starts.
  2. Google ML Kit detects a stable face and the app captures a photo automatically.
  3. The capture repeats until 7 images are taken, and each is sent as Base64 to the backend.
  4. Spring Boot forwards the images to the Python AI service.
  5. SCRFD detection, quality checks and alignment run, then ArcFace produces a 512-dimensional embedding.
  6. The embedding is stored in PostgreSQL.

Attendance flow

  1. Faculty opens the full-screen attendance camera with a 3×3 composition grid. The grid is only a guide and is not part of the photo.
  2. They capture 5 to 10 classroom photos and upload them, which creates an attendance session.
  3. The session is set to PROCESSING and a background worker sends the photos to the AI service.
  4. SCRFD detects multiple faces and ArcFace embeddings are compared with the enrolled students.
  5. The result is matched students and unknown faces, and the session moves to REVIEW.
  6. Faculty resolve the unknown faces and confirm, and the session becomes FINAL. If processing fails it becomes FAILED.

Key features

  • Automatic face capture: The enrollment camera detects a stable face and captures the 7 images without any button presses.
  • Face quality validation: The AI service checks each image before an embedding is created.
  • Multi-photo classroom attendance: Several classroom photos are processed together to recognize many students at once.
  • Unknown-face review: Faces that do not match are shown to faculty, who can link them to the right student before confirming.
  • Role-based access: Separate ADMIN, FACULTY and STUDENT roles.
  • JWT with refresh tokens: Access and refresh tokens, with automatic token refresh in the Flutter API client.

How it is built

  • Backend in Java with Spring Boot 3: authentication, business logic, enrollment, attendance sessions and persistence.
  • JWT security with Spring Security, access and refresh tokens and role-based authorization.
  • Asynchronous attendance processing: the upload returns quickly while a background worker calls the AI service.
  • PostgreSQL storage for users, enrollments, embeddings and attendance.
  • A clear split of work: the Flutter app handles the camera, live face detection and API calls, while the Python service creates the final ArcFace embeddings and does the matching.
  • Privacy practices from the project guide: keep face images, Base64 data, database credentials and JWT secrets out of Git, restrict access to biometric data and use HTTPS in production.

Status

In active development. Planned next: attendance analytics, reports and export, admin improvements, production deployment and security hardening.

Online Restaurant Food Ordering & Table Booking

A restaurant management application that takes a customer from booking a table to ordering, paying and being served, with a Java Spring Boot backend, a React and TypeScript frontend and role-based access.

The journey it supports

  1. The user logs in and opens the dashboard.
  2. They book a table, and the booking goes through an approval step.
  3. They view the menu, which loads from the backend database.
  4. They add items to the cart, using the menu IDs generated by the backend.
  5. They check out and pay, and the order is confirmed.
  6. The chef is notified and prepares the food.
  7. The waiter is notified and serves the food.
  8. The order is marked completed and the table is freed.

Key features

  • Table booking: Users book a table and bookings go through an approval step before the table is held.
  • Menu from the database: The menu page loads from the backend, so the database is the single source of truth for items, prices and categories.
  • Cart, checkout and payment: The cart works with backend-generated menu IDs, followed by checkout, payment and order confirmation.
  • Kitchen and floor workflow: The chef and the waiter are notified at the right stages, from food preparation to serving.
  • Order completion: When an order is completed, the table is freed for the next booking.
  • Admin menu import: An admin-only endpoint imports menu items in bulk and creates categories automatically.

How I built it

  • Backend REST APIs in Java with Spring Boot 3.2 on Java 17, with business logic kept in service classes.
  • The admin menu import: the /admin/menu/import endpoint, the importMenuItems() service method, the getOrCreateCategory() helper and the request and summary DTOs.
  • Import safety: the import is transactional and idempotent, so running it more than once does not create duplicates.
  • Security with JWT token validation and role-based access control, with admin-only endpoints for menu management.
  • Database design for categories and menu items with a relationship between them, using PostgreSQL.
  • Frontend work in React and TypeScript: the menu page, a menu source state that tracks whether items come from the backend, a fallback so the page never shows empty, and the admin API client.
  • A shell script that imports the starting menu of 23 items across 6 categories using an admin token.
